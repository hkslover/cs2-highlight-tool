# 07：两仓库联调与最终验收

前置：01–06。此步收敛已实现行为，不添加新的快捷项、历史体系或发布流程。

## 集成顺序

1. 核对桌面端 DTO、shared types、backend contract/adapter、生成绑定、debug events 与插件消息名/字段。确认全部协议有明确归属，正式 queue/take/history 不消费 debug 事件。
2. 插件从指定源码仓库构建 Release x64，用 debug DLL override 选择 `static/cs2/server.dll` 做联调。两仓库提交与 DLL 路径分别记录；不得用旧下载 DLL 代替新版后宣称功能通过。
3. 执行桌面端 `go test ./...`、`cd frontend && npm test`、`npm run build`，检查插件 MSBuild 结果。维护根/子 AGENTS 与插件 README 中已经实现的协议；删除临时占位控件与虚假状态。
4. 对照下表逐条 Windows 实测，失败回到所属步骤修复，不通过新增庞大防御框架掩盖功能问题。
